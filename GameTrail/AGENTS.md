# GameTrail 游戏资源预热器

## 使用

Windows x64 便携版为 dist/GameTrail-0.6.15.exe（0.6.15）。双击后启动器将内嵌的 Node、工作台与浏览器解压到本次启动专用的临时目录，正常退出时清理。设置、缓存、报告和已保存的重放任务继续使用原数据目录。发行时只需复制这个 EXE。

macOS arm64 发行包名为 dist/GameTrail-0.6.9-macOS-arm64.zip。解压并双击 GameTrail.app，程序会在默认浏览器打开本地工作台。发行包自带 Node、Chromium、WebKit 和 Apple Vision 文字识别组件。右上角“退出程序”关闭服务；运行中先点“停止”。关闭工作台标签页后，可再次打开应用。

1. 默认入口为虚构模板 `https://game.example.invalid/play/{gameId}?lang={lang}`，启动前请换成实际入口。变量按行填写，例如 `gameId=demo-a,demo-b,demo-c` 和 `lang=en-US,fr-FR`。组合按配置框的行顺序由外到内展开，每行按填写顺序取值，替换 URL 时编码。多变量回放中，第一行当前值的所有环境结束后才开始下一个值，同一值内可并发。只有一个模板变量时，各值的环境仍可并发。单任务的模板组合数和运行数均无固定上限。选择两个设备、按 gameId 隔离并开启探索时，共执行 3 次发现和 12 次回放。
2. 勾选设备。内置 Windows Chrome、macOS Safari、iPhone 和 Android 的横竖屏预设。Safari 和 iPhone 预设在两种主机上均使用 WebKit。Android 竖屏与 iPhone 竖屏共用 390×664 CSS 像素视口、390×844 屏幕和 3 倍像素比。自定义配置在“自定义机型与探索参数”里填写，离开输入框后即可勾选。例如：
   
   ```json
   [{"id":"tablet","name":"平板横屏","engine":"chromium","viewport":{"width":1024,"height":768},"deviceScaleFactor":2,"isMobile":true,"hasTouch":true}]
   ```

3. 点击“启动任务”。每个入口和设备使用单独的浏览器上下文；模板变量 lang 同时设置浏览器 locale。录入和发现串行运行。普通资源加载和路径重放均按环境并发，每个环境内的路径依次执行；“并发实例数”留空时取本任务所选机型数，填写 1 可串行运行。启动已保存任务时同样采用工作台的并发设置。每个环境从开始导航起默认最多等待 60 秒；按来源和路径去重的 GET 全部结束且连续一个静默窗口无新活动时提前继续。工作台可配置 GET 静默窗口（0.1–30 秒，默认 1 秒），重载入口和点击后等待也采用该窗口。已收到入口响应但资源仍在下载时，到上限即继续；未取得入口响应时，导航超时记为异常（最多 45 秒）。手动录入每条路径最多 100 个动作。源码模式每个发现环境默认最多试 8 个函数；切换到按钮模式时，同一参数表示每条路径的最大点击深度。页面加载等待上限可设为任意正整数秒。
4. 工作台顶栏显示当前服务版本。运行监控默认展开可横向滚动的实例预览列表，约每 1–2 秒更新一次，可折叠。时间线和任务历史显示北京时间，新写入的逐请求日志使用带 +08:00 偏移的时间戳。时间线可筛选异常、探索、iframe 或缓存命中。总进度包含发现和回放运行；GET 200 指标按完整 URL 去重。同 URL 跨设备或语言的具体结果可查逐请求日志。黄色和红色事件附文字。顶部异常次数统计网络失败及 HTTP 4xx/5xx。
5. 任务报告支持勾选多项或全选，确认后删除所选任务的报告、日志和截图。
6. 在“任务报告”打开某个环境的结束截图，展开成功资源清单，或下载 JSON 和 NDJSON。report.json 中的 runs 数组记录入口、设备、变量和异常数。resources[].runs 可反查各资源出现在哪些环境。events.ndjson 记录时间、运行序号、方法、URL、HTTP 状态、来源和探索事件。报告保留完整 URL，使用生产 token 时需注意报告的存放与分享范围。

## 手动录入特殊路径

新配置默认使用“手动录入特殊路径，再批量重放”。升级时保留已保存的探索方式，可在工作台切换。勾选“开启探索与重放”，选择主隔离变量（例如 gameId）后启动。程序先在后台用每组的首个原始输入和首个所选机型加载游戏，工作台可查看实时预览。工作台可跳过该游戏，也可选择“录入当前画面”。主变量留空时，每个输入与机型组合各自成组。

点击“录入当前画面”后，工作台打开可操作的实时画面窗口，同一 Playwright 页面继续运行，保留加载进度、计时器和内存状态。窗口传入的点击或触屏轻触只用于当下操作，常规点击保存可重新定位的 DOM 或 Cocos 动作。点“结束录制并验证”后才从入口和新的浏览器上下文试播。通过的路径加入本组，可以在试播结果上继续录制（新路径包含已验证的前缀），也可点“重新预览入口”准备独立路径。自动验证和手动试播期间（含入口加载时）以及结果页均可点“从入口重新录制”。工作台会丢弃当前路径，重新打开入口，等用户点击“录入当前画面”后从第一步开始。其他路径保留。自动验证、手动试播及批量重放每条路径都从新的上下文开始。截图步骤匹配失败时，时间线和该环境的任务报告提供诊断图，使用当次扫描画面标注候选位置、相似度和倍率；文字区分无达标目标、出现多处候选或未取得截图。所有组处理完毕后再按原始输入与机型组合批量运行。跳过的组仍正常加载入口。实时预览是截图，录制操作请在单独打开的实时录制窗口完成。等待人工操作期间可从工作台停止整个任务。

进入批量重放时，程序将本次配置、各组已录路径（含截图样本）保存到数据目录的 replays.sqlite，并按环境独立保存路径进度。SQLite 的 replay_progress 表保留乱序完成和部分完成的环境，事务同步推进连续完成的环境游标，兼容旧版续跑位置。“已保存的重放任务”按入口主机、北京时间和短标识自动命名，支持重命名、勾选单项或多项删除。停止任务或重启服务后，点“继续重放”会从上次中断的环境和路径入口开始；已经成功或按规则失败跳过的路径都计入进度。升级前已保存的任务续跑时沿用原环境顺序，全量重跑时改用保存的变量配置顺序。点“全量重跑”可调整此任务保存的模板变量，每行填写一个值。确认后保存新变量，按新组合重算环境数并从头重放；再次中断可按新进度续跑。按主变量分组时复用同值的已录路径；主变量留空时按原变量组合和机型匹配。没有对应路径的环境只加载入口，之后重新加入原组合仍可使用原路径。两种操作均复用已录路径，各自生成本次执行的报告。删除保存的任务和删除历史报告可分别操作。

可录制的动作包含具有唯一稳定属性（id、data-testid、name 或 aria-label）的 DOM 点击控件，以及 Cocos 场景中能够唯一定位的按钮 clickEvents 绑定。录制时从真实手势捕获绑定，保存节点名称路径、组件标识、处理方法和可重建的参数。回放使用当前会话的组件绑定与自定义事件数据，DOM 控件则运行其 click 动作。子 frame 按名称或唯一来源与路径匹配。普通点击没有可调用绑定时，若 Cocos 节点分发了可识别的触摸或鼠标事件、名称路径唯一且可投影，程序记录目标节点及按下位置相对其边界的比例。节点自身未提供世界边界时，录入和重放通过 UITransform 的尺寸与锚点取节点自身的四角，再用渲染该节点的相机投影到画布。回放重新定位并在对应画布内点击或轻触。同一按钮先收到触摸按下、鼠标按下和触摸结束后，随后落到其他节点的鼠标释放事件不计为第二个录入目标。其他情况下，同一次手势命中多个不同目标、仅命中全屏容器或无法映射坐标时可使用框选。普通录入按语义定位；主动框选时会额外保存所选按钮的像素样本。未识别的画布点击、歧义节点和无法重建的参数只提示该步已跳过、路径可能无法完整重放，后续动作继续录入；验证成功的路径以 skipped 记录跳过次数。

录制中遇到无法识别的按钮时，可以继续，也可以点击“暂停录入”并在游戏里手动回到点击前的画面。按 F（或点“框选按钮”）冻结录制窗口的当前画面，拖框圈住有辨识度的按钮图案，Esc 可取消。松开后会在实时游戏里重新匹配图案、点击并恢复录入。暂停期间用于返回的操作不计入路径。按 F 时通过 /api/record-freeze 取得当前页面的 JPEG。冻结与匹配都使用质量 95、原 CSS 视口分辨率的 JPEG。框选动作保存最长边 128 像素的 PNG 选区及 32×32 采样；试播和批量回放按步骤顺序立即扫描当前视口，未找到唯一匹配时隔 200 毫秒重扫，匹配后点击当前位置。每种倍率按录入框中心的相对位置从近到远分块扫描，仍检查整个视口的重复目标。缺少录入位置的旧样本继续按行扫描。即使同时识别出语义绑定，框选步骤也按图点击。连续框选步骤忽略人工停顿，下一步直接开始扫描。工作台“自定义机型与探索参数”可设置每步等待超时（1–120 秒，默认 15 秒）与截图最低相似度（1–100%，默认 94%）。新路径按亮度分布、颜色与特征点误差计算相似度。能定位选区所在 Canvas 时记录所在 frame、画布与有效视口大小，回放结合画布和页面尺寸尝试邻近倍率并重新搜索位置。已有 20×20 样本继续使用原 RGB 算法。试播和批量重放每等待满 10 秒降低 1 个百分点，最低为 1%。只有一个有效目标时点击。降阈值后的首次有效扫描若由零个目标变为至少三个，立即记录失败并跳过该路径。恰有两个时继续扫描，原超时时间照常生效。图案随语言或动画改变、相同图案多次出现或选区几乎纯色时，可能无法匹配。请尽量避开背景和动态文字。

试播和批量回放在下一步是 DOM 或 Cocos 绑定时立即尝试调用，目标尚未就绪时每 200 毫秒重试，最多 15 秒。最后一步仍等待 GET 稳定。每条手动路径独立启动浏览器，结束后依次关闭上下文和浏览器。工作台增量轮询只传输监控所需状态，完整环境明细保存在报告中。

验证逐步检查动作能否在新会话重新定位并调用，还检查录制期间观察到的后代 HTTP(S) frame 地址是否再次出现（匹配来源与路径，忽略查询参数，独立的语言路径段按当前 lang 匹配）。仅有 Canvas 画面变化时，程序能验证调用，画面效果可在工作台的实时预览中人工核对。游戏若依赖精确触摸数据、真实用户激活、键盘或未暴露的引擎绑定，相关动作可能无法重放。只支持在原游戏标签页及其子 frame 内录制。每组路径随本次任务写入 report.json。

## 架构和运行边界

本机网页工作台通过 HTTP JSON 调用 Node 服务。服务只绑定 127.0.0.1，默认选用空闲端口。UI 每 600 毫秒按事件序号增量读取最近的请求；完整事件逐行写入任务目录。预览展开且工作台可见时，前端独立请求 /api/preview，按任务和运行序号获取当前环境最新打开页面的 JPEG 截图。列表按运行序号分别展示各实例的浏览器截图，不会发起第二次游戏导航。每个实例在内存中保留最近一帧和采集时间。预览请求立即返回已有 JPEG，首帧未就绪时返回 204。可见工作台的轮询按需触发后台采集，每个实例最多每秒启动一次，录制窗口使用 100 毫秒间隔；同一实例同时只采集一张预览图，正在获取匹配或冻结 JPEG 时跳过预览采集。工作台显示画面距今秒数。手动框选的 JPEG 截图解码、20×20 和 32×32 样本的匹配在复用的 Node 工作线程中执行。线程数为可用逻辑核数减一，限制在 1–4；扫描按提交顺序排队，每个回放环境一次只提交一张图。步骤超时或停止任务会移除排队的扫描，正在计算的线程会终止并释放名额。失败诊断图复用对应原始 JPEG。服务一次执行一个任务，SQLite 写锁使同一数据目录只有一个服务实例。

任务调度器将模板组合与设备预设展开为运行列表。每个运行启动静音的无头浏览器（Chromium 显式使用 --mute-audio 启动，Windows 上使用新版无头模式，由浏览器为 WebGL 选择可用的图形后端，WebKit 在每个 frame 初始化时静音 Web Audio 输出，并在媒体加载、播放和音量变化时保持静音；Windows 版另在导航前启动音频助手，每 100 毫秒检查输出设备，将当前服务所属 WebKit 进程新建的 Windows 音频会话设为静音，随浏览器退出），在导航前注册上下文级请求/响应、失败和子 frame 导航监听。页面正常发出的 POST 会保留原方法。浏览器实际访问的第三方资源同样记入报告。游戏自己的动态 JS、嵌套 frame 和接口由浏览器执行。Service Worker 默认禁用以保证请求可观察，因此依赖其离线逻辑的站点可能表现不同。

主隔离变量取自入口模板，含 `{gameId}` 的模板默认使用 gameId。自动源码或按钮模式下，每个值先在其他变量的首组取值与首个所选设备上发现路径，后续遇到同组组合时直接复用路径。将 lang 写在第一行并按 gameId 隔离时，同一语言的游戏全部回放后再切换语言。主隔离变量留空时各环境独立探索。探索库按任务保存，report.json 的 pathGroups 记录各组走到深度上限或无按钮可点的完整路径，每步含标签页、frame 路径、定位信息及 frame 内的 CSS 像素坐标。工作台显示当前分组、阶段、在试路径及已记录路径数，可在历史报告中展开路径。

工作台可选“分析源码，直接调用 iframe 函数”。浏览器在游戏脚本执行前安装扫描器，在入口等待结束后检查各标签页和 frame 中可取得的函数源码，包括新增的全局函数、全局对象自有方法、Cocos 场景组件原型方法、部分已注册的交互监听器和内联 onclick。匹配创建 iframe、插入 iframe HTML、查找 iframe、设置 iframe/WebView 地址或创建 Cocos WebView 等代码（含同一对象或全局函数间的一层具名委托）后，在原对象上调用函数。普通函数限无需必填形参的候选，监听器会收到合成事件。每个候选从入口状态尝试，切换候选时重新载入入口。调用后 4 秒内若观察到当前 frame 的后代发生 HTTP(S) 导航，就等待资源稳定并保存函数路径；重放时按标签页、frame 路径和函数标识重新匹配。时间线记录候选、导航 URL 及未观察到导航的结果，直接调用的物理点击数为 0。

源码模式采用运行时可访问函数的源码特征匹配。模块私有且未暴露的函数、依赖业务参数或特定前置状态的入口、混淆过的间接调用都可能漏检。页面自身的定时导航也可能恰好落入观察窗口。源码模式找不到候选时结束本次探索；需要原有交互路径时，可在工作台选择“按按钮深度优先探索”。

按钮模式的探索器对页面、弹窗与嵌套 frame 内当前可见的 DOM 按钮、链接、注册点击监听的元素、Cocos Creator 2.x Button、可见 Canvas 文字和无文字图标进行定位。Mac 使用 Vision，Windows 可通过 Tesseract 识别，语言包由 GAMETRAIL_OCR_LANG 指定，默认 eng。发现阶段首次试点同一画布时，先用约 5 秒多帧观察标记自行变化的图块。同层连续试点共用这段观察。点击前复核文字或图标轮廓及位置，点击后等待 GET 稳定，再检查可见画布中原先稳定的相邻图块是否持续变化，远处打开的面板也可作为反馈。页面跳转、原 frame 消失或打开新标签页也视为反馈。一次发现运行中，若点击后确认无稳定反馈，则记住该标签页、frame 路径和画布中的 OCR 文字；后续扫描、切换分支和重载入口时直接略过，即使文字位置变化也生效。原位置附近的 OCR 结果若仅漏掉一个字母或汉字，且较短文字至少四个字符，也视作同一文字。新一轮发现重新判断。点击前已移动、消失或截图失败的文字可在后续扫描中重试。轮播停留时间超过观察窗口仍可能误判，仅有短暂反馈的按钮也可能被跳过。无文字图标通过 Canvas 截图中的紧凑高对比轮廓产生候选，每张画布每次最多试选 12 个，优先较大的外轮廓，并跳过与已识别文字重叠的区域。无稳定反馈的图标按画布、位置及形状去重，回放时按相对位置和轮廓特征重新定位。低对比、紧贴复杂背景、外形过大或过小的图标仍可能漏检。

每次点击后重新扫描当前画面，按 DFS 顺序逐个走完分支。同一路径相邻两步不能点击同一个按钮，经过其他按钮后可再次点击。仅剩上一步的按钮时，复扫后记录当前末端路径。无按钮时会短暂复扫，再记录末端路径。自动发现点击后最多等待 3 秒或配置的静默窗口（取较大值）再扫描。分支数量随按钮数和深度增长，可在工作台停止任务。切换兄弟分支时重新载入入口并重走公共前缀，游戏保存在浏览器上下文中的进度可能影响复现。

回放每条路径从入口开始，按当前环境重新匹配按钮坐标。从入口导航或每次点击开始，每个来源（协议、主机、端口）的每个路径只将首个 GET 纳入稳定判定，忽略查询参数和片段。等待这些请求下载结束或失败，并连续一个配置的静默窗口没有计入判定的 GET 活动。重复心跳仍正常发送并写入逐请求日志。点击后单次等待达到 45 秒会报告超时，跳过失败路径；入口资源等待达到配置上限即继续，入口导航失败仍记为异常。发现和回放各自保留结束截图。

## 缓存

默认容量 1 GiB，可改为 0–100 GiB，设为 0 会清空并禁用。容量约束针对响应正文文件；索引、任务报告、浏览器临时目录独立计量。命中后直接向浏览器返回已存正文，并记录 source=cache。需要确保访问到代理时，可在任务前清空缓存并将容量设为 0。

SQLite 保存键、大小、命中次数、最近使用时间、到期时间和响应头。静态资源按 URL 的协议、主机、端口和路径计算 SHA-256，以摘要作为索引键和正文文件名。查询参数、片段、设备、语言、Cookie 和来源页面不参与区分。例如同一站点的 /asset.png?v=1 与 /asset.png?v=2 在有效期内复用同一份文件。0.3.1 及更早版本的索引只保存旧键的哈希，升级后按新键重新积累，旧条目计入容量并按原淘汰规则处理。

浏览器原生静态资源以及 fetch/XHR 加载的常见图片、音视频、字体、JSON 和游戏包均可缓存，仅接收 GET 200。遵守 max-age、Expires，并可用 Last-Modified 估算最长一天的有效期。缺少这些信息时，扩展名前带 5–64 位十六进制指纹的静态资源估算有效期为一小时并扣除 Age，其余重新请求。带 Authorization、Range、条件请求头、常见凭据查询参数或明确要求回源的请求绕过缓存。响应带 Set-Cookie、private、no-store、no-cache 或 Vary 指定 Cookie、Authorization、* 时跳过。单条正文上限 16 MiB。WebKit 静态资源请求中的 no-cache、Pragma: no-cache 和 max-age=0 允许复用相同来源及路径的有效缓存。请求 no-store 仍绕过缓存。命中数跨任务保存，降低容量时按命中次数、最近使用时间依次淘汰。

在时间线选择“缓存写入与跳过”，可查看符合资源类型的网络 GET 200 的写入结果、策略跳过原因或正文读取失败。逐请求日志以 kind=cacheDecision 保存这些事件。

source=network 表示浏览器观察到网络响应，cache 表示本机命中。若浏览器直接连接 CDN，代理不会收到该请求。要确认反向代理端文件完整写入，需要对接该代理的写盘记录。本版本没有接入代理管理接口。

## 从源码运行

安装 Node.js 24（含 node:sqlite），在项目根目录执行下列命令。macOS 和 Windows 使用相同的启动入口。

```sh
npm ci
npm run browsers
npm start
```

macOS 源码运行时可用 `swiftc -O native/vision.swift -o native/vision` 启用系统 OCR。Windows 在没有 Tesseract 时仍可运行 DOM 和 Cocos 识别。macOS 13 的浏览器和 Windows Chromium 固定使用 Playwright 1.48.2。Windows WebKit 由独立锁定的 webkit-win（playwright-core 1.65.0）启动，内嵌 WebKit 27.2（revision 2388）。升级时同步更新 lockfile，复核 TLS 补丁与浏览器 ABI，并运行两种引擎的回归测试。Windows x64 在安装项目依赖、执行 npm run browsers 后用 npm run package:win 打包。构建需要 Windows .NET Framework 4.x 的 x64 C# 编译器和 Node 24+ x64，可通过 GAMETRAIL_NODE 指定内嵌 Node。

```sh
npm test
npm run package:mac
```

macOS 打包需要 Swift 编译工具和 Node 24。可用 GAMETRAIL_NODE 指定打包时内嵌的 Node 路径。发行包在本机生成。打包脚本在资源及 Info.plist 就位后为完整 App 执行 ad hoc 签名，通过 codesign --verify --deep --strict 校验后再生成 ZIP。此版本未使用 Developer ID 签名或 Apple 公证。

macOS 默认数据目录为 ~/Library/Application Support/GameTrail，Windows 为用户目录的 .gametrail 子目录。GAMETRAIL_DATA 可覆盖路径；PORT 可固定端口；GAMETRAIL_NO_OPEN=1 关闭自动打开浏览器。cache/ 保存正文及索引，settings.json 保存最近的任务配置，reports/ 按任务保存报告、结束截图和原始事件。手动清缓存仅清理 cache/ 中的资源条目。

## Windows WebKit 0.6.4

Windows 上的 Safari 和 iPhone 预设通过 WebKit 自身执行 JavaScript、WebAssembly、渲染和网络请求。测试游戏的 HTTPS 登录和 WSS 实时连接共用一个含下划线的主机名。LibreSSL 4.3.3 默认在客户端生成 TLS SNI 前拒绝这种名字。补丁只在客户端校验时将下划线视为字母，发送原始主机名，证书信任链、证书主机名和浏览器跨域检查仍由原流程处理。

native/windows-webkit/ssl-60.dll 从 OpenBSD 的 libressl-4.3.3.tar.gz 构建（SHA-256 为 ff97c432457f349e6ba3d416ab903bc7468f1436f0f32efe5fff808de292c7b8）。重建时在解压后的源码根目录执行 patch -p1，传入 native/windows-webkit/client-sni.patch，并在顶层 CMakeLists.txt 末尾追加 set_target_properties(crypto ssl PROPERTIES PREFIX "") 以匹配包内 DLL 名。用 MSYS2 UCRT64 GCC、CMake 3.31.6 和 Ninja 配置 Release 共享库，设置 BUILD_SHARED_LIBS=ON、LIBRESSL_TESTS=OFF、LIBRESSL_APPS=OFF、ENABLE_ASM=OFF，然后构建 ssl 目标。只取生成的 ssl/ssl-60.dll，配套使用浏览器自带的 crypto-57.dll。启动器内嵌的浏览器目录带有 LibreSSL-COPYING.txt。
Windows x64 发行包验收使用单文件 EXE、独立数据目录、5 秒 GET 静默窗口，依次加载《海盗女王 2》的桌面 Safari 与 iPhone 竖屏环境。两个环境均到达“继续”画面，各记录 280 个去重 GET URL；第三方上报、排行榜等异常保留在报告。独立 WebKit 探针收到了游戏 WSS 数据帧，本地 TLS 用例验证原始下划线主机名进入 ClientHello，未受信任证书仍被拒绝。
