# FlowSentinel · 流程哨兵

Windows x64 桌面程序：录制 Chrome 中的操作，按配置并发无头回放，用局部图像巡检并自动恢复。

## 直接运行

双击 `FlowSentinel-1.4.2-win-x64.exe`。这是便携启动文件，无需安装 Node.js 或开发环境。首次打开需要解压内置运行时，稍等片刻。升级前先退出旧版，新版会读取原来的本机加密流程。

需要本机安装 **Google Chrome**。若安装位置不标准，在界面中选择 `chrome.exe`。已在 Windows 11 x64、Chrome 和本地 Vue 3 表单上验证。本版本未购买商业代码签名证书。

## 切换主题

右上角“主题”可选择浅色、暗色、适应系统。默认跟随系统，手动选择自动保存，重启后保留；适应系统实时响应 Windows 的应用颜色模式变化。

## 录制一个流程

1. 点击“新建录制”，填写名称，保持默认 1280 × 720 视口，点击“打开 Chrome 并录制”。
2. 程序会打开独立的空白 Chrome。在地址栏输入目标网址，正常登录、填写表单和点击。
3. 页面加载完毕、下一步可以执行时，可回到 FlowSentinel 点击“＋ 继续执行检查点”，框选已就绪的稳定图标，设置超时和匹配率，插入后继续操作。可插入多个检查点。流程全部完成时点击“最终巡检截图”，框选最终正常状态，保存。
4. 点击“结束录制”。步骤、输入数据和可信图像随录制自动保存，不需要额外导出。
5. 可将录制字段改为随机模板，设置实例数、检查间隔和重试策略，点击“启动任务”。
6. 顶栏和配置区都有停止按钮。停止会取消等待并关闭本程序的执行浏览器；平时使用的 Chrome 不受影响。

录制浏览器使用独立会话，不导入日常 Chrome 的 Cookie。每次回放从新会话开始，因此需要把登录步骤录入。录制页可以关闭，但尚未选可信区域的流程不能启动巡检。手动删除流程会删除它的步骤、输入数据、可信图像和故障截图。

## 录入和运行子流程（1.3.0）

1. 选择已录制或导入的主流程，在“子流程”区域点击“录入子流程”。主流程必须有网址和最终可信截图。
2. 等待可见 Chrome 回放主流程并通过最终可信图检查。此阶段不采集操作；失败按主流程恢复上限重试，达到上限则结束创建。
3. 设置必填条件：框选触发截图，或用每 N 秒、每 N 分钟、每小时、每天的控件生成 crontab，也可直接填写六段表达式（兼容旧版五段）。设置条件前可以准备页面状态，准备动作不记录；确认条件后开始录制后续动作。
4. 正常操作 Chrome，可插入截图检查点。点击“完成动作，预览保存”，填写名称（预填默认名称）并保存。至少需要一个动作，检查点本身不计作动作。
5. 已保存子流程可展开预览、删除，不支持修改。Chrome 保持打开；点击“继续录入新的子流程”保留当前标签页和画面，不再重放主流程。保存后及设置触发条件期间均暂停采集，可以先手动调整到想录入的位置，再确认截图或定时条件开始录制；这些准备操作不会保存为步骤。点击“停止录入子流程”或关闭 Chrome 才退出。未保存草稿丢弃，已保存内容保留，以后可以继续追加。

录入期间禁止启动主流程或其他任务。任务启动后，先回放主流程并等待最终可信图达标，再按固定 200ms 轮询间隔、保存顺序检查子流程；每实例串行执行，实例间隔离。截图条件只要仍匹配，每轮都会触发。

定时使用运行电脑的本地时区，六段为“秒 分 时 日 月 星期”。`*/5 * * * * *` 为每分钟第 0、5、10…55 秒；`30 0 9 * * 1-5` 为工作日 09:00:30。支持数字、范围、列表、步长，星期 0/7 为周日。日期和星期同时指定时按任一匹配触发。同一秒每实例最多成功执行一次。旧版五段表达式仍按分钟匹配和去重，不会升级成每秒执行。每 N 秒/分钟按分钟/小时边界计算，并非从启动时间累计间隔；不补跑长动作期间错过的时刻。子流程检查独立于巡检间隔，每轮检查和执行结束后等待 200ms，截图、匹配和动作耗时会延长实际周期，因此秒级表达式不保证准点完成。最终可信图仍按配置的巡检间隔检查，耗时子流程结束后才处理到期巡检，不积压补跑。含六段定时条件的 .fs 文件要求导入版本至少为 1.3.2。

动作执行期间不并行巡检。失败通过主流程恢复重新建立工作状态，复用操作超时、检查点超时及恢复上限；失败的定时子流程在恢复后重试。子流程新打开的标签页执行结束后关闭，主流程原有标签页保留。触发截图应取自主流程已经打开的标签页。

子流程随完整流程加密保存，界面预览不显示表单原值。导出包含全部子流程，含子流程文件最低导入版本为 1.3.0；旧版无子流程文件仍可导入。

## 整字段随机与片段随机

录制后，在“表单变量”中找到字段，选择“使用字段模板”，填写模板，然后保存配置或直接启动。

| 模板 | 含义 |
| --- | --- |
| `{{int:1000:9999}}` | 整个字段使用 1000–9999 的随机整数，两端都包含 |
| `138{{digits:8}}` | 固定前缀 138，后面拼接 8 位随机数字 |
| `user_{{digits:6}}@example.com` | 只随机邮箱中间的数字部分 |
| `{{letters:8}}` | 8 位随机小写英文字母 |
| `task_{{instance}}_{{uuid}}` | 固定前缀、从 1 开始的实例编号和随机 UUID |
| `A{{int:1:9}}-{{digits:4}}Z` | 同一字段组合多个随机片段 |

数字串保留前导零；普通整数不补零。数字串和字母串长度为 1–128；整数范围限于有符号 32 位整数。模板最长 2000 字符。随机数不保证唯一，需要唯一标识时优先使用 UUID。

每个实例、每次完整回放独立生成一组值。同一次回放中同一字段如果被填写多次，将复用同一个值。恢复时从头回放，因此会重新生成。使用“录制原值”时继续填写原来录入的固定值。登录账号密码一般应保持录制原值。

## 可信图像与恢复

### 中途检查点与回放速度（1.1 新增）

默认启用“忽略录制时的停顿”，步骤之间仅保留可配置的操作间隔（默认 200 毫秒）。真正的悬停动作仍然执行，以支持悬停菜单；Canvas 拖动轨迹内部的时间也保留。取消这个选项可恢复按录制时间等待，并受“录制等待上限”限制。

对于异步加载的 Canvas，元素已显示不代表内容已加载。应在加载完成、下一次点击之前插入继续执行检查点；重放会约每 500 毫秒检查一次图像，达到该检查点的匹配率才继续。检查点有自己的超时（默认 60 秒，可设 1–600 秒）和阈值。超时后不执行后续步骤，保存证据并按恢复策略处理。等待中可随时点击停止。

框选期间暂停记录页面事件，保存或取消（包括 Esc）后恢复记录；网页自身仍继续运行，框选期间请不要操作网页。检查点会随流程自动加密保存。最终巡检截图用于流程完成后的持续检查，两者用途不同，均需分别设置。旧流程可以读取，但不会自动推断业务就绪条件；需要检查点时请重新录制，或使用已经验证的修复副本。

### 最终巡检

选取正常页面中稳定、独特的图标或状态标志，至少 12 × 12 像素。尽量避免大面积空白、时钟、动画、闪烁光标和会随账号变化的文字。

执行时截取固定视口，优先在录制位置及附近的容差范围寻找图像，用颜色容差下的一致像素比例作为匹配率。这不是语义识别，也不是全网页任意位置搜索。默认允许位置偏移 12 像素，匹配率至少 90%。字体、渲染或布局改变可能需要降低阈值或重新录制。

默认每 15 秒检查一次，连续 3 次不通过后保存故障截图、保留当前实例的浏览器和上下文，关闭全部旧标签页后新开标签页从头回放；浏览器断开、上下文失效或标签页清理失败时重新启动浏览器。默认连续恢复上限为 5 次，超过后显示“需要人工处理”。连续 5 次健康检查后恢复次数归零。其他实例继续运行。

恢复会重复执行整个流程。包含提交、创建记录等步骤时，应确保业务允许重复执行。图像仍然存在不代表业务一定有心跳；本版本按用户所选画面是否存在进行判断。

## 支持范围

- 表单：文本、密码、textarea、可编辑区域、checkbox、radio、原生 select。
- 交互：点击、双击、右键、停留悬停、常用键盘操作、页面与元素滚动。
- Canvas：鼠标点击和拖动轨迹、按键、滚轮；在元素实际边框内按相对坐标回放，不需要读取 Canvas 像素内容。
- iframe：支持跨域和嵌套框架；通过 Playwright 在每个文档内独立记录，通过框架路径回放，不关闭浏览器同源安全机制。
- 弹出标签页：同一浏览器上下文内按创建顺序关联，检查最近操作标签页的可信区域。
- 支持静音、禁用后台计时器节流、可见或无头执行。
- 每个实例独立 Chrome 进程和登录会话，互不共用 Cookie；并发设置为 1–64，实际容量由网页和本机资源决定。建议先验证 1 个，再逐步增加。

不录制操作系统原生文件选择窗口、浏览器扩展界面、验证码人工验证、触控多指手势或任意桌面操作。浏览器 alert/confirm/prompt 在回放时默认取消，依赖这些对话框的业务流程需要进一步适配。Canvas 的布局或内容位置发生大变化时，相对坐标轨迹可能不再对应同一业务对象。禁用节流不会绕过网站自己的暂停机制，也不能让电脑休眠后继续执行。

## 数据与日志

界面右上角“打开数据目录”可打开实际保存位置，通常位于 `%APPDATA%\flow-sentinel`。

- `flows/*.flow`：步骤、表单值、配置、随机模板、可信图像作为一个整体使用 Windows 用户绑定加密后保存。自动保存采用临时文件替换。
- `activity.log`：结构化运行日志，超过 5 MiB 轮换为 `activity.previous.log`；界面显示最近 1500 条。
- `evidence/<流程ID>/instance-<编号>-last-failure.png`：各实例最后一次图像异常截图，会覆盖旧图。图片本身未加密，可能包含网页信息。
- `evidence/<流程ID>/instance-<编号>-last-error.png` 和 `.json`：回放或检查点异常的截图、步骤号及错误类别，方便定位等待在哪一步失败。

日志不写表单值或生成的随机值，也不直接输出可能包含密码的 Playwright 调用日志。数据加密绑定当前 Windows 用户，不适合把 `.flow` 文件直接复制到另一台机器当作可移植配置。程序不上传录制数据。

## 从源码运行

```powershell
cd D:\code\FlowSentinel
npm ci
npm start
```

要求 Node.js 22.12 或以上。依赖版本通过 `package-lock.json` 锁定。Electron、Playwright、pngjs 是程序运行基础；Vue 只用于本地测试页，不随产品运行依赖分发。

```powershell
npm test
npm run test:e2e
node test/checkpoint-e2e.js
node test/ui-smoke.js
npm run dist
node test/ui-smoke.js --packaged
node test/portable-smoke.js
```

集成测试会打开专用 Chrome 和本机临时 HTTP 服务器，使用测试账号，不访问实际业务站点。GUI 测试需要先运行 `test:e2e` 生成样例流程。打包产物输出在 `dist`。

## 源码结构

| 文件 | 职责 |
| --- | --- |
| `src/main.js` | Electron 生命周期、受限 IPC、任务调度与日志 |
| `src/engine.js` | Chrome 录制会话、框架定位、并发回放与恢复 |
| `src/recorder-script.js` | 各文档内的 DOM、Canvas、键盘事件记录 |
| `src/variables.js` | 字段身份、模板校验、随机值生成 |
| `src/vision.js` | PNG 裁剪、局部图像匹配 |
| `src/store.js` | 加密流程文件与原子保存 |
| `src/ui` | 深色桌面工作台、变量编辑、框选与滚动日志 |
| `test` | 单元测试、Vue/跨域 iframe/Canvas 集成测试、GUI 验收 |

## 排查问题

Chrome 无法启动：确认已经安装 Google Chrome，并在界面明确选择可执行路径。

回放等待超时：先取消“无头运行”，用可见浏览器观察停在哪一步；适当提高单步超时。网站 DOM、iframe 或 Canvas 布局变动后可能需要重新录制。

图像一直不匹配：查看故障截图和步骤号。若 Canvas 还在加载，在后续操作前录制就绪检查点；若图标存在却不通过，重新框选静态图标内部，避开发光边缘、动画和背景，再检查位置容差与最低匹配率。

相同账号互踢：浏览器会话虽隔离，但服务器仍可能限制同账号多端登录，需要使用网站允许的账号策略。

点击停止：等待中的任务会立即被取消，正在启动或关闭 Chrome 时需要短暂完成进程清理。关闭主程序也会清理正在运行的录制和执行浏览器。

## 1.2.0：不同座位的 Canvas 点击定位

重新录制需要适配座位的流程，点击稳定且独特的按钮图案。步骤列表会显示点击前的 48×48 局部截图。回放先检查原位置；不匹配时在该实例的画布内搜索，按记录的点击偏移执行。找不到或发现多个目标时回退录制原坐标继续执行，日志记录原因和坐标。

普通表单继续使用 DOM 定位；拖动保持原轨迹。旧录制兼容，但不会自动补出截图。透明/空白或无法读取的 Canvas 会显示重新录制提示。1.2.1 使用浏览器点击前合成画面兜底，无需先悬停在按钮上；请等待页面画面显示后再点击。图标旋转、尺寸变化和动态背景不保证匹配。若不同座位使用完全相同的图案，此方法无法判断哪个属于自己；原位置匹配仍会优先复用。

中途检查点及最终可信图请选固定位置的稳定标志，避免选择随座位移动的炮台。可执行文件为 `dist/FlowSentinel-1.4.2-win-x64.exe`。

## 1.2.1：大厅截图采集修复

大厅画面清晰却被判为空白时，新版会在 Canvas 读回失败后使用浏览器实际显示的点击前画面，支持透明叠层、跨域图片污染及 WebGL 缓冲区被清空的情况。没有改动匹配阈值，截图图案确实不足时会显示缩略图和准确提示。旧流程缺失的截图无法凭空恢复；1.2.2 可以直接按原坐标回放，若希望启用图像重定位才需要重新录制。

## 1.2.2：图像辅助定位，失败回退原坐标

原位置匹配时点击原位置；不匹配时扫描当前画布，唯一匹配则点击新位置；找不到或多个匹配则点击录制原坐标并继续。截图不可用、旧版本保存的截图错误或损坏图片也使用原坐标。日志输出回退原因与坐标。无需重录即可使用此策略，原流程数据不会被改写。截图检查点和最终巡检仍按原配置等待或恢复。

## 1.2.3：连续加注等同点点击

紧接着重复点击同一按钮时，首次成功匹配后，后续点击复用本段已确认的坐标，避免按钮的点击反馈状态导致重复匹配失败。日志会显示“连续同点点击第 N 次”。每下仍独立执行，点击次数和配置间隔保留。换按钮、画布变化、导航、检查点或中断后重新定位；不同实例不共享位置。首击未匹配时仍采用 1.2.2 的原坐标回退。已有流程无需重录。

## 1.2.4：按钮外围背景变化

完整截图找不到目标时，增加中央 32×32 特征匹配，避免动态背景或滚动条使按钮首击定位失败。阈值仍为 90%，多候选仍回退原坐标并记录日志。首次匹配后连续同点点击继续复用已确认坐标，已有流程无需重新录制。

## 1.2.5 无头巡检截图

勾选“无头运行”后，每次最终巡检会在匹配结果日志下显示当前目标页面的缩略图，正常和匹配失败都会显示。点击缩略图放大，点击大图切换原始尺寸，按 Esc 或点击“关闭”返回。

图片最多保留最近 64 张，并受 24 MiB 编码大小上限约束；较早图片显示“截图已释放”，文字日志继续保留。截图仅在本次应用运行期间可查看，不写入 activity.log；退出应用后不保留。有头运行时仍显示文字巡检日志。

## 导出到其他电脑 / 导入流程

1. 停止录制或巡检，选中流程；配置如有修改，先点击“保存配置”。点击“导出流程…”，在保存对话框选择位置（默认下载目录），保存 .fs 文件。
2. 在另一处 FlowSentinel 点击左侧“导入流程…”，选择 .fs。软件先校验协议，再弹出名称对话框，默认保留原名。
3. 如提示重名，修改名称；点击“确认导入”。新流程会出现在列表并被选中，不会覆盖原流程或自动执行。取消不会保存。

.fs 未加密，包含录制的表单原值（包括密码）和参考图片，请妥善保管。导入后的本机流程仍使用 Windows 用户绑定加密。Chrome 的自定义路径也会随配置保留，换电脑后如路径不同需重新选择。

导入功能从 1.2.7 开始提供；同协议且软件达到文件声明的最低导入版本即可导入。协议不兼容时显示所需最低版本；软件版本较新但协议仍兼容的文件可以导入。损坏的数据会拒绝，文件大小上限为 128 MiB。

## 1.2.8 恢复时复用缓存

自动恢复保留该实例 BrowserContext 内的资源缓存、Cookie、登录态及 localStorage，sessionStorage 随旧标签页关闭释放。每轮仍重新生成随机字段值并从第一步执行，因此流程需要兼容已有登录态。不同实例仍独立，不读取本机日常 Chrome 缓存，也不共享首个实例的缓存。缓存是否命中取决于网站的 Cache-Control、有效期及缓存淘汰；no-store 等资源仍需重新请求。停止任务、达到恢复上限或退出程序会关闭浏览器，缓存不跨任务保留。

## 按名称筛选流程（1.2.9）

在左侧“按名称筛选”输入名称片段，即时过滤已创建和导入的流程；忽略大小写、首尾空格及全角/半角差异。筛选时显示匹配数 / 总数，无结果时显示提示。点击“清空”或按 Esc 恢复全部列表。筛选不改变当前选中的流程、配置或运行任务；新建和导入的流程同样遵守当前筛选条件。筛选条件仅在本次窗口会话内保留。

连续录入时，原有额外标签页也保持打开。子流程回放只预先具备主流程标签页；若需操作新的标签页，请在本次动作录制期间录入打开它的操作。不能直接把上一子流程遗留的额外标签页当成本次回放前提。

## 1.4.0 基础流程

左侧可切换“全流程”和“基础流程”，新建时选择类型。基础流程用于保存登录等准备操作与表单模板，结束录制后保存表单配置；它不包含子流程、截图检查点或最终可信图，也不能单独巡检。

创建全流程时选择一个基础流程，程序沿用其视口和表单模板，打开 Chrome 后自动回放；日志提示完成后再操作浏览器，继续录制并设置最终可信截图。准备期间可以停止，失败时不会转入人工录制。基础流程的“执行配置”仅保留最低匹配率、图像位置容差、单步超时、保留录制间隔上限、固定操作间隔、检查点默认超时、忽略录制停留时间。嵌入后基础步骤使用这七项配置，其余参数继承全流程；后续步骤及最终巡检使用全流程配置。基础流程仍不支持录制检查点或独立巡检，匹配相关设置保留为执行配置，现有 Canvas 点击匹配阈值不受它们影响。基础步骤只回放一次。

嵌入为独立快照，原基础流程后续修改或删除不影响已有全流程。全流程可独立调整表单模板。只能导入导出全流程；导出会携带内嵌基础流程，导入时分别填写全流程与基础流程名称，重名必须修改。导入后的基础副本可用于后续新建全流程。内嵌基础流程的文件要求 1.4.0 或更新版本。
